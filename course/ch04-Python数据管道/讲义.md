## 4.1 "能跑"和"能交付"差了 6 件事

| # | 能跑 | 能交付 |
|---|---|---|
| 1 | 路径写死 `C:/Users/me/下载/a.csv` | 路径来自配置 |
| 2 | `print("done")` | 日志分级 + 落文件 + 可检索 |
| 3 | 出错直接 traceback 崩掉 | 分层处理 + 异常清单 + 退出码 |
| 4 | 重跑会重复插入 | 幂等（重跑结果一致） |
| 5 | 每次都全量跑 | 支持 `--start/--end` |
| 6 | 没有测试 | 有单测 + 黄金数据集回归 |

这 6 件事，就是**第 7 章部署**和**第 8 章上线**的全部前提。
你现在写的是要交给业务用的东西，不是作业。

## 4.2 项目结构：先立规矩，再写代码

```
project/
├─ config/settings.yaml     配置（不含密钥）
├─ .env.example             密钥样例（真 .env 进 .gitignore）
├─ src/pipeline/
│   ├─ config.py            读配置、校验、给默认值
│   ├─ transform.py         纯函数：输入 dataframe/list → 输出，不碰 IO
│   ├─ report.py            渲染，不碰数据源
│   └─ main.py              CLI 入口：参数、日志、编排、退出码
├─ tests/test_pipeline.py   对 transform 的断言
├─ output/                  产物（每次重跑覆盖）
└─ logs/                    日志（按天切分）
```

### 三条铁律

1. **`transform` 里不许有 `open()`**：纯函数才好测。IO 全在 `main`/`extract`。
2. **配置里不许有密钥**：密钥走环境变量。
3. **入口只有一个**：`python -m pipeline.main`。不要有 5 个 `run_xxx.py`。

## 4.4 日志：`print` 是给写代码的人看的，`logging` 是给运维看的

```python
logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s %(levelname)-7s %(name)s | %(message)s",
    handlers=[logging.FileHandler(log_dir / "run.log", encoding="utf-8"),
              logging.StreamHandler()],
)
```

**必须进日志的 5 件事**：

1. 启动参数（start/end/配置路径）
2. 每个数据源读了多少行
3. 被过滤掉多少行、为什么（取消单/重复/未映射）
4. 关键指标结果（金额、行数）
5. 异常与耗时

**日志里绝对不能出现**：API Key、买家姓名地址、完整订单明细。
（合规风险，第 7 章会展开。）

## 4.5 错误处理：三层

| 层 | 例子 | 处理 | 影响 |
|---|---|---|---|
| **可恢复** | 非关键文件缺失、某天数据为空 | 记 ERROR，写进异常清单，继续 | 结果不完整但可用，退出码 1 |
| **需告警** | 对账残差超容差、行数异常 | 记 ERROR，写清单，**退出码 1** | 产物生成但要人看一眼 |
| **致命** | 配置文件不存在、**关键数据源缺失**、start > end | 抛出/直接 return，**退出码 2** | 不产出任何东西 |

> **"关键"是设计决策，不是技术细节。**
> 业务报告（主表）没了 → 什么都算不出来 → 致命。
> 广告报表没了 → 还能出日报，但残差会刚好等于缺的广告费 → 可恢复 + 告警。
> 这个区分要在 PRD 里写清楚，而不是等出事时临时决定。

**退出码约定**（方便 cron / Airflow / 告警系统判断）：

```
0 = 全部成功
1 = 部分失败（有异常清单，产物可用）
2 = 致命失败（无产物）
```

> 新手最常犯：出错就 `except: pass`，或者 `sys.exit(0)` 掩盖失败。
> **一个静默失败的定时任务，比没有这个任务更危险。**

## 4.6 幂等与增量

### 幂等（Idempotent）

同一份输入，跑 100 次，结果完全一致。

实现方式（从简到严）：

1. **覆盖写**：输出文件名固定，每次覆盖（最简单，够用）
2. **原子替换**：先写 `.tmp`，成功后 `os.replace()` 改名（防半截文件）
3. **按分区覆盖**：按日期/站点分区，只覆盖本次范围
4. **去重键**：入库前按业务主键 `DELETE` 再 `INSERT`（upsert）

### 增量（Incremental）

```
--start 2026-11-01 --end 2026-11-30
```

三个要点：
- **默认值**：不传就是昨天（定时任务的常态）
- **边界**：闭区间还是半开区间，写进文档
- **回补**：支持指定历史区间重跑，且不重复

**自测**：跑两次 `--start 2026-11-01 --end 2026-11-30`，两次产物 `md5` 必须相同。

## 4.7 数据契约：三道校验

| 校验 | 做法 | 失败后果 |
|---|---|---|
| **结构** | 必需列齐全、类型可解析 | 该文件跳过，进异常清单 |
| **数量** | 行数/件数在合理区间（如 180 行 ±0） | ERROR + 退出码 1 |
| **金额** | 对账残差 ≤ 容差（如 1.00） | ERROR + 退出码 1 |

```python
assert set(REQUIRED_COLS) <= set(df.fieldnames), "缺列：..."
```

**为什么"结构校验"值钱**：平台每年改几次报表格式，你的管道第一次遇到新格式就崩了。
有 schema 校验，它会在**改版当天**告诉你"少了 refund_amount 列"，而不是三个月后财务发现数不对。

## 4.8 测试：三层，从便宜到贵

| 层 | 测什么 | 成本 | 本例 |
|---|---|---|---|
| **单测** | 纯函数（时区换算、去重、指标） | 秒级 | `transform` 的每个函数 |
| **集成** | 读真实文件 → 出产物 | 秒级 | 跑一遍 11 月数据 |
| **回归** | 结果与"黄金数字"比对 | 秒级 | 销售额必须 = 46,322.64 |

**黄金数字**（golden numbers）是数据工程最重要的测试手段：
把一次人工核对正确的输出固化成断言，以后每次改动都跑一遍。
第 3 章你算出来的那个对账桥，就是黄金数字。

```python
def test_sales_total(self):
    self.assertAlmostEqual(kpis["sales_usd"], 46322.64, places=2)
```

## 4.9 CLI：参数要少，默认要对

```bash
python -m pipeline.main --start 2026-11-01 --end 2026-11-30
python -m pipeline.main                    # 默认跑昨天
python -m pipeline.main --help             # 必须有
```

- 参数超过 6 个 → 该进配置文件了
- 默认值要能"什么都不传直接跑"
- `--dry-run` 很值钱（只校验不产出）

### 一个真实的交付细节：CSV 的 BOM

业务方不会"用 UTF-8 导入"，他们只会**双击**。
中文 CSV 没有 BOM，Excel 打开就是乱码 → 他们会认为你的工具坏了。

| 用途 | 编码 | 原因 |
|---|---|---|
| 给人看的 CSV（异常清单、日报导出） | `utf-8-sig`（带 BOM） | Excel 双击不乱码 |
| 给程序读的 CSV | 纯 `utf-8`（无 BOM） | 有 BOM 会把第一列名变成 `\ufeffdate`，join 失败 |

**这个约定要写进数据字典**，否则下一个人接手必踩。

## 4.10 十个坏味道

1. `except: pass`
2. 路径写死绝对路径
3. 密钥写在代码里
4. 每次全量重算（跑了 3 小时）
5. 输出没有时间戳/没有 run_id，出问题无法追溯
6. `print` 当天日志，第二天找不到
7. 一个函数 200 行，什么都干
8. 没有 `--help`
9. 数据库连接不关（Windows 上会锁文件）
10. 用 `float` 存金额（该用整数分或 Decimal）
