## 任务 1｜让 9 个测试全绿（本章主体，3–4 小时）

按依赖顺序实现（别跳）：

### Step 1 — `config.load_config`
- 读 YAML，相对路径相对**项目根目录**（`config/` 的父目录）解析
- 缺的键用 `DEFAULTS` 补
- 密钥从 `os.environ` 读，**不能出现在 `repr(cfg)` 里**

**验收**：`python -c "..."` 打印出 cfg，`data_dir` 是绝对路径且存在。

### Step 2 — `transform.read_csv` / `load_sources`
- 用 `csv.DictReader`，保留空字符串
- 用 `REQUIRED_*` 校验列，缺列抛 `ValueError`（消息里带文件名和缺的列名）
- **文件不存在不要崩**：记到 `missing` 列表里继续

> 为什么要这一步：讲义 4.7 的"结构校验"。
> 平台改报表格式时，这是你唯一的早期预警。

### Step 3 — `site_date_from_bj`（3 行代码）
- 北京时间 -16h = 站点日期
- 先过两个测试再说

### Step 4 — `dedupe_by`
- 按 key 保留首次出现，保持原顺序
- 顺手记一下去了几行（后面日志要用）

### Step 5 — `build_daily_asin`（最难，占一半时间）
按讲义 3.9 的构建顺序：

```
business（打底，180 行）
  ← ads（先聚合到 日×ASIN，父体要摊到子体）
  ← settlement（用 erp 的 order_id 关联到下单体，聚合到 日×ASIN）
  ← storage（月度，只挂月末）
```

**三个必踩的坑**（第 3 章答案里都写过，但你自己踩一遍才记得住）：
1. 广告不先聚合 → 行数变 210 甚至更多
2. 父亲广告不摊到子体 → `Σad_spend = 1058.16` 而不是 `2362.54`
3. 费用按 `posted_date` 归集 → 跨月的费用丢失

### Step 6 — `compute_kpis`
- `acos = ad_spend / ad_sales`、`tacos = ad_spend / sales`
- **分母为 0 返回 `None`**，不要抛异常

### Step 7 — `reconcile`
- 桥的每一行都要能对上第 3 章的数字
- `residual` 必须是 `0.00`

### Step 8 — `report.render_markdown`
- 金额千分位 + 2 位小数；百分比 2 位
- 没有数据写 `—`，不要写 `None`

### Step 9 — `main.setup_logging` / `run`
- 日志双写（文件 + 控制台），文件 utf-8
- 原子写：先写 `.tmp`，成功后 `os.replace`
- 退出码：`0 / 1 / 2`

## 任务 2｜幂等验证（20 分钟）

```bash
python run.py --start 2026-11-01 --end 2026-11-30
# 记下 md5
python run.py --start 2026-11-01 --end 2026-11-30
# 再算一次
```

Windows 算 md5：

```powershell
Get-FileHash output/daily_asin.csv -Algorithm MD5
Get-FileHash output/report.md -Algorithm MD5
```

**要求**：两次完全相同。
如果不同，先想清楚是**时间戳进了产物**（那就把时间戳移出产物，放进日志），还是**排序不稳定**（那就显式 sort）。

## 任务 3｜故障演练（40 分钟，本节最能体现工程能力）

三个实验，逐个做，记录现象：

| 实验 | 操作 | 期望 |
|---|---|---|
| A 关键源缺失 | 把 `business_report_us.csv` 移走（指向一份临时数据副本） | 直接终止；**退出码 2**；**不产出**任何文件 |
| B 非关键源缺失 | 只移走 `ads_campaign_daily.csv` | 不崩；**退出码 1**；产物仍生成；**对账残差应正好等于 −2,362.54**（缺的广告费） |
| C 配置缺失 | `python run.py --config nope.yaml` | 打印"配置文件不存在"；**退出码 2** |
| D 金额被篡改 | 在临时副本里把某笔结算金额改掉 100 美元 | 残差 ≈ 100 → 超容差 → ERROR + **退出码 1** |

**验证退出码**（管道会吞掉退出码，别用 `| Out-Null`）：

```powershell
python run.py --start 2026-11-01 --end 2026-11-30
$LASTEXITCODE
```

> 注意实验 B：**残差不是随便一个数，而是精确等于缺失的那部分金额**。
> 这说明你的对账不是"凑到 0"，而是真的在做**差额归因**。
> 这是本章最值得记住的一句话：**一个能定位缺失数据的对账，比一个总能凑平的对账值钱 10 倍。**

**做完把三个实验的现象贴给我**——这是本章最重要的产出，比 9 个测试通过更重要。
