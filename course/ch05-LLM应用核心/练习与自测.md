## 任务 1｜让 9 个测试全绿（主体，3–4 小时）

按依赖顺序实现：

### Step 1 — `schema.has_chinese` / `validate_listing`
- 中文判定：`"\u4e00" <= c <= "\u9fff"`
- 返回**未通过**的规则名列表
- 注意：`bullets` 不是 5 条时，不要再查长度规则（避免一次报两个错）

### Step 2 — `schema.parse_json`
模型会输出这些花样，全都要能解析：

```
1) {"title": ...}
2) ```json\n{...}\n```
3) 好的，以下是结果：{...} 希望有帮助
4) 前面废话 + 半个 JSON + 后面废话
```

第 4 种用"截取第一个 `{` 到最后一个 `}`"兜底。都不行才能抛。

### Step 3 — `llm.estimate_tokens` / `estimate_cost`
- 英文 ≈ 4 字符/token，中文 ≈ 1.5 字符/token（粗估够用）
- 单价表在 `PRICES`，注意单位是**元/百万 token**

### Step 4 — `llm.mock_complete`（本章最有意思的一个）
要求：从 prompt 文本里抠出关键词和卖点，拼一份**一定能通过校验**的 JSON。

三个必须解决的问题：
1. **标题 60–180 字符**：太短要补，太长要截
2. **每条 bullet 120–300 字符**：5 条都要够长
3. **必须含 ≥2 个目标关键词**：从 prompt 的"目标关键词："那一行提取

> 提示：可以先按模板拼，再 `while len(x) < 120: x += " ..."` 补齐。
> 别做得太聪明——mock 的职责是**合规**，不是**好看**。

### Step 5 — `prompt.load_template` / `build_messages`
- 模板里的 `{xxx}` 用 `str.format(**values)` 填
- 注意模板里有字面量 `{{"title": ...}}`，要正确转义成 `{"title": ...}`

### Step 6 — `evaluate.score_listing` / `summarize`
- 空列表要返回全 0，不能除零
- `failed_rules` 按次数**降序**

### Step 7 — `main.read_products` / `load_done` / `generate_one` / `write_report` / `run`
- `generate_one` 的重试循环是重点（见任务 4）
- 产物三件：`out/listings.jsonl`、`out/report.md`、`out/failed.jsonl`

## 任务 2｜跑通全链路并读报告（40 分钟）

```bash
python run.py --mock
```

**产出的报告要能回答这 4 个问题**（把答案写下来）：

1. 通过率是多少？平均得分多少？
2. 失败规则分布是什么？（如果全是 0 条失败，说明你的 mock 太完美——这正是重点，见下）
3. 总成本是多少？平均每条多少？
4. 重试率是多少%？如果为 0，是好事还是坏事？

> 第 2 题的思考：**mock 全过，只能证明管道通，不能证明模型行。**
> 所以真实项目的报告里，`--mock` 的报告应该被**明确标注为非生产数据**。
> 这是一个很容易犯的错误：拿 mock 的 100% 通过率去汇报。

## 任务 4｜依赖注入与重试测试（90 分钟，本章的技术核心）

现在 `generate_one` 直接调 `llm.complete`，**测不动**。

**4.1** 改造签名，让 `completer` 可注入：

```python
def generate_one(product, template, *, mock, max_tokens, temperature, completer=None):
    completer = completer or llm.complete
    ...
```

**4.2** 写三个测试（放在 `tests/test_retry.py`，这题不检查，但要写）：

| 测试 | 假 completer 行为 | 断言 |
|---|---|---|
| 第一次就成功 | 返回合法 JSON | `attempts == 1`，`ok == True` |
| 第二次成功 | 第 1 次返回坏 JSON，第 2 次返回好的 | `attempts == 2`，`ok == True` |
| 三次都失败 | 一直返回坏 JSON | `attempts == 3`，`ok == False`，`failed` 非空 |

**4.3** 回答：为什么"3 次都失败"时，要把最后一次的错误写进 `failed.jsonl`，而不是只写"failed"？

> 提示：三个月后你只会拿到这个文件，靠它改 prompt。
