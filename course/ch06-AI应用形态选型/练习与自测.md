> 及格线：top1 ≥ 70%，误拒率 ≤ 10%。

## 任务 5｜改造拒答逻辑（60 分钟，产品思维）

现在的拒答是"一刀切"：没命中就说"没找到"。

**5.1** 改成**二级策略**：

- 分数 ≥ 0.35：直接答 + 引用
- 0.10 ≤ 分数 < 0.35：答，但**开头加提示**"未找到明确条款，以下内容可能相关，请核对原文"
- < 0.10：拒答

**5.2** 跑你评估集里的"应拒答"样本，看是否会误答。

**5.3** 写 100 字，说明这个改动的**收益**和**风险**。

> 提示：真实业务里，"答一半"往往比"拒答"更有用；
> 但如果你不标注置信度，业务会把它当确定答案用——**这才是风险**。

## 任务 6｜Agent 雏形（90 分钟，选做但强烈建议）

不改现有代码，新建 `agent/react.py`，把 `retrieve.search` 注册成**工具**：

```python
TOOLS = {
    "search_kb": lambda q: [{"doc": c.doc, "section": c.section, "text": c.text[:120]}
                            for c, s in rt.search(index, q)],
    "calc": lambda expr: str(eval(expr)),      # 只做教学，真实项目禁止 eval
}
```

**6.1** 手写一个 ReAct 循环，用**脚本化的假 planner**（不用模型）跑通：


**6.2** 加两个刹车：
- 最大步数 8，超了返回"无法在限定步数内完成"

## 任务 8｜自审：它会怎么答错（30 分钟）

列出这个 RAG **最可能答错的 5 种情况**，每种给一个触发例子。

参考方向（不要照抄，写你自己的）：

- 同义词：问"仓储成本"但文档写"仓储费"（双字分词能覆盖一部分）
