## 任务 1｜八道选型题参考答案

| # | 首选 | 理由 | 为什么不选另一个"看起来合理"的 |
|---|---|---|---|
| 1 | **规则脚本 + 定时任务** | 判据是固定阈值，数据在库里 | 不用 Agent：多一步模型只增加成本与不确定性；早会数据"错"比"慢"严重得多 |
| 2 | **RAG** | 需要引用原文、政策会更新 | 不用微调：政策一改就要重训，且无法给出处；不用纯 Prompt：模型会编条款 |
| 3 | **规则脚本**（阈值筛选）+ **可选**模型解释 | "花费 ≥ 100 且 0 单"是纯规则 | 不用 Agent：一步 SQL 的事；不用纯模型：会让它算数，可能算错 |
| 4 | **Agent（带查询工具）** | 要先查订单号再写回复，多步 | 不用纯 Prompt：没有订单信息只能编；不用 RAG：这是"查实时数据"不是"查知识" |
| 5 | **Prompt + 结构化输出**（或文档解析库） | 单次抽取，输出 schema 固定 | 不用 Agent：没有多步决策；注意表格类 PDF 用纯 LLM 不稳，必要时上专用解析 |
| 6 | **浏览器自动化** | 没有 API，只能点页面 | 不用 Agent 点页面：本质还是自动化，套 Agent 只增加不确定性；先确认真的没有 API/导出接口 |
| 7 | **规则脚本**（DOI + 日均销量） | 纯算术 | 不用模型：会算错数且不可审计 |
| 8 | **Prompt 批量调用** | 单次翻译改写，可批量 | 不用 RAG：不需要检索；不用微调：100 条样本不值得 |

**评分要点**：
- 只写形态不写理由 → 半分
- 没写"为什么不用 X" → 不通过。**选型能力的本质是排除法。**
- 场景 3、7 答成"用 AI 分析" → 直接不合格（这是本章最想纠正的直觉）

## 任务 3｜调参结论（方向比数字重要）

| 实验 | 现象 | 原因 |
|---|---|---|
| A `MAX_CHARS=200` | top1 **下降**、误拒**上升** | 切太碎，一段完整规定被拆开，单块信息不足 |
| B `MAX_CHARS=800` | top1 略降、**检索变慢**、答案带无关内容 | 块太大，一块里混多个主题，向量被稀释 |
| C `min_score=0.02` | 拒答准确率**下降**（该拒答的没拒） | 阈值太低，噪音也算命中 → 开始"编" |
| D `min_score=0.12` | 拒答准确率**上升**、误拒率**上升** | 阈值太高，相关但表述不同的问法被挡掉 |
| E `boost_weight=0` | "月度仓储费"排第一变成**长期仓储费** | 长文档天然占优，**篇幅长 ≠ 相关** |
| F `boost_weight=0.6` | 标题含词的排得过前，可能压掉更相关的正文 | 重排过头会掩盖内容匹配 |

**三个必答问题的标准答法**：

1. **切碎 vs 切大**：太碎 → 语义不完整、召回率高但答案没用；太大 → 主题混杂、
   相似度被稀释、还浪费 token。**最佳块大小取决于文档结构，不是固定值**——
   所以按小节切（结构边界）比按字数切更稳。
2. **min_score 的两面性**：它同时控制"拒答准确率"（高）和"误拒率"（低）。
   调它是**在两种错误之间移动**，不是"越严越好"。要用评估集选点。
3. **boost=0 时排第一的是"长期仓储费"**：说明纯向量相似度会被**篇幅和共现词**
   带偏。这就是为什么生产 RAG 几乎都有 rerank 层。

## 任务 4｜知识库可维护性

- 加文档不改代码，`load_docs` 用 `glob("*.md")` 自动发现。
- 如果答不出来，先看**定位顺序**（这是本题真正的考点）：

```
① 新文档有没有被切成 chunk？（load_docs 打印 chunk 数）
② 那个 chunk 的 token 与问题有没有交集？（tokenize 后对比）
③ 有没有命中但被 min_score 挡掉？（临时把阈值调到 0 看分数）
④ 有没有命中但排在后面？（看 top10 而不是 top3）
```

- **"加文档不用改代码"是 RAG 相对微调的最大优势**：知识更新是运营动作，
  不是工程动作；微调则是"每更新一次政策，就要重训 + 重新评估"。

## 任务 5｜二级拒答的权衡

**收益**：召回"部分相关"的内容，业务能拿到线索；避免"一律不知道"造成的工具不可用感。

**风险**（这才是评分点）：
1. 用户把"可能相关"当成"确定答案" → **必须显式标注置信度**
2. 中间档内容可能是错的 → 要有"上报纠错"的入口
3. 阈值 0.10–0.35 是拍的 → 要用评估集验证这一档的准确率

**参考答法**：
> 收益是把"半个答案"变成可用线索，减少无效提问；风险是用户忽略提示语直接采用。
> 所以我加了两条约束：提示语放在**答案最前面**（不是结尾），
> 且每条都带引用，用户点开就能核对原文。

## 任务 6｜Agent 刹车

参考实现要点：

```python
MAX_STEPS = 8
seen = Counter()

for step in range(MAX_STEPS):
    action, arg = planner(history)
    key = (action, str(arg))
    seen[key] += 1
    if seen[key] > 2:
        return "检测到重复调用，已终止（可能是死循环）"
    ...
else:
    return "无法在限定步数内完成"
```

**评分点**：
- 有没有**最大步数**（没有 = 不能上线）
- 有没有**重复调用检测**（只有步数上限不够，8 步同一动作也是浪费钱）
- 有没有把**每步的工具与参数打进日志**（事后排查唯一依据）

## 任务 8｜它最可能答错的五种情况

参考：

1. **同义词**：问"仓储成本"，文档写"仓储费"——双字能覆盖一部分，但"运费 vs 配送费"就不行
2. **跨文档**：问"退款影响利润吗"，答案在 returns 与 settlement 两篇，top1 只取一篇
3. **时效**：文档写过"费率 X"，实际已调整；检索不会告诉你"这条过期了"
4. **数字**：问"具体多少钱"，文档只写"按体积计费"，无法给数
5. **多跳**：问"A 和 B 的区别"，需要分别检索再对比，单轮检索做不到

**加分**：说出"应对办法"——如给文档加 `effective_date` 并在答案里回显，
跨文档类问题做"两次检索"，数字类问题**拒答并给官方链接**。
