# 第 9 章 · 作品集、项目讲述与面试表达

> **本章目标**：把你做过的项目，变成**一份作品集 + 一段 15 分钟的讲述 + 扛得住追问的答案**。
>
> 前八章解决"会不会"；这一章解决"**能不能证明你会**"。
> JD 明确要求："能够**展示并讲清**至少一个本人主要参与或独立完成的应用或自动化项目。"

---

## 9.1 面试官到底在评估什么

四个维度，权重从高到低：

| 维度 | 他们怎么判断 | 你的材料 |
|---|---|---|
| **业务理解** | 你能不能说出"这个工具帮谁省了什么" | 项目背景 + 效果数据 |
| **能不能独立干** | 你是一个人做完的，还是只写了其中一段 | 贡献边界 + 技术细节 |
| **讲不讲得清** | 15 分钟能不能让非技术的人听懂 | 讲述稿 |
| **靠不靠得住** | 你知不知道自己方案的缺陷 | 取舍 + 复盘 |

**最容易挂的一点：只讲技术，不讲业务。**
面试官（尤其是业务线主管）关心的是"这东西有用吗"，不是你用了什么框架。

---

## 9.2 作品集的三件套

| 载体 | 内容 | 作用 |
|---|---|---|
| **一页纸**（PDF/Markdown） | 背景、方案、结果、截图 | 面试时给面试官看 |
| **代码仓库** | README + 可运行 + 有测试 | 证明是真的 |
| **Demo**（可选） | 5 分钟能跑通的演示 | 加分项，别现场翻车 |

### 一页纸的结构（严格一页）

```
1. 一句话概述        （是什么 + 给谁用 + 效果）
2. 问题与背景        （数字化现状痛点）
3. 方案与架构        （一张图 + 3 句话）
4. 关键取舍          （2–3 个"为什么不用 X"）
5. 结果              （前后对比表 + 基线来源）
6. 我的贡献          （独立完成 / 占比多少）
7. 已知不足与下一步
8. 链接              （仓库、截图）
```

> **第 4 和第 7 部分最容易被忽略，也最能拉开差距。**
> 敢写"我没做什么、哪里不行"的人，可信度立刻上一个台阶。

## 9.3 项目讲述：六个部分，15 分钟

```
① 背景（2 分钟）    谁、什么场景、多大痛点，带数字
② 目标（1 分钟）    做成什么样算成功（可衡量）
③ 方案（3 分钟）    整体怎么走，一张图讲清
④ 取舍（4 分钟）    ★ 分水岭：为什么不用另外三种方案
⑤ 结果（3 分钟）    前后对比 + 基线来源 + 局限
⑥ 复盘（2 分钟）    如果重做，会改什么
```

### ④ 取舍怎么讲（这 4 分钟决定你的档位）

**模板**：

> "这件事有三种做法：A 规则脚本、B RAG、C Agent。
> 我选了 A，因为**规则能写下来**，而模型的成本和不稳定性没有换来额外价值。
> 我特别考虑过 C，但 Agent 需要多次调用，一步错了后面全错，
> 而这份数据是要在早会上用的——**错了比慢了严重得多**，所以不上 Agent。"

三个要点：
1. **给出候选**（说明你想过，不是碰巧）
2. **给出判据**（成本/确定性/维护/时效）
3. **结合业务后果**（"早会用，错了更严重"）

### 讲述的四个禁忌

| ❌ | 为什么 |
|---|---|
| 从"我用了 Python + FastAPI + …"开始 | 面试官不关心技术栈，先讲问题 |
| 全程讲技术细节 | 业务主管会走神，技术面试官会追问你没准备的地方 |
| 只讲成功 | 显得不真诚，且经不起追问 |
| 说"这个很简单" | 要么显得没价值，要么显得你没遇到真问题 |

## 9.4 数据怎么讲

### 三段式

```
① 基线从哪来    "让小李记了 3 天的实际耗时，平均 55 分钟"
② 前后对比      "上线 3 周 42 次，工具平均 6 秒，省了 34 小时"
③ 主动说局限    "这是过程指标；业务结果我只观察到 1 次避免断货，约 3000 美元，样本太小"
```

### 第 ③ 步为什么重要

面试官见过太多"我做了个工具，效率提升 80%"。**主动划清边界的人，反而显得专业。**

参考句式：
> "我能证明的是 X；Y 我没有足够数据，只能说观察到了 Z。"

## 9.5 高频追问 30 题（按类别）

### A 业务与需求（6 题）

1. 这个需求是谁提的？你怎么确认它值得做？
2. 如果业务方说"我就想要个按钮"，你怎么处理？
3. 你有没有做过"没人用"的东西？为什么？
4. 你怎么排优先级？举个当时的具体例子。
5. 你怎么证明"省了时间"？基线哪来的？
6. 这个工具停了会怎样？谁来找你？

### B 数据（6 题）

7. 你的数据从哪来？时区怎么处理的？
8. 你的数和业务手上的数不一样，你怎么解释？
9. 数据缺失/脏数据你怎么处理？
10. 你怎么保证重跑结果一致？
11. 退款的归集口径你选的是哪个？为什么？
12. 如果上游改了报表格式，你怎么第一时间知道？

### C 技术与方案（8 题）

13. 为什么不用现成的 SaaS / 开源方案？
14. 为什么不上向量库 / 为什么用 TF-IDF？
15. 你的 prompt 怎么管理的？改了怎么验证没变差？
16. 模型输出不合法怎么办？
17. 你怎么控制成本？
18. 为什么不用 Agent？
19. 这套东西挂了怎么恢复？有回滚方案吗？
20. 你怎么测试一个"不确定输出"的系统？

### D 落地与协作（5 题）

21. 怎么让业务真的用起来？
22. 有人抵触怎么办？
23. 你怎么做培训？讲多久？
24. 上线后你怎么知道它今天比昨天差？
25. 你和一个不懂技术的同事怎么沟通需求？

### E 失败与反思（5 题）

26. 讲一个失败的项目。
27. 你做过最有争议的技术决策是什么？
28. 如果重做，你会改什么？
29. 你的方案最可能在什么情况下崩？
30. 你怎么判断一个项目该止损？

> **每一题都能对应到前面某一章**（第 2 章需求、第 3 章口径、第 5 章评估、第 7 章部署、第 8 章推广）。
> 如果你答不上来，回去看那一章，而不是背话术。

## 9.6 简历条目怎么写

### 公式

```
动词 + 对象 + 方法 + 量化结果（含口径）
```

### 对照

| ❌ 弱 | ✅ 强 |
|---|---|
| 负责公司日报自动化 | 独立开发多站点日报管道（Python，无第三方依赖），把 8 站点手工汇总从 55 分钟/天降到 5 分钟/天，上线 3 周累计节省约 34 小时；通过对账桥定位到平台佣金多收 215 美元/月 |
| 使用大模型生成 Listing | 构建带 schema 校验的 Listing 批量生成器（mock/real 双模式 + 3 次校验重试），8 产品评测通过率 100%，单条成本 0.0031 元 |
| 搭建知识库问答 | 实现离线 RAG 问答（中文双字分词 + TF-IDF + 章节重排 + 拒答阈值），无关问题拒答率 100%，top1 命中率 __% |

**三条铁律**：
1. **每条都要有数字**（没有数字就写口径和范围）
2. **写清"独立"还是"参与"**（面试必问）
3. **不写你不会被追问的东西**（写了就要能答）

## 9.7 Demo 的 5 分钟脚本

```
0:00  一句话：这是什么，解决什么问题
0:30  跑一次（成功路径）—— 提前准备好输入，别现场下载
2:00  展示关键输出（日报/清单/引用），指出一个真实发现
3:00  跑一个"故意失败"的场景（坏输入 → 拒答/告警）
4:00  打开日志/健康检查，说明"它自己会告诉我坏了"
4:30  留 30 秒给提问
```

**为什么要有第 3 步**：**失败场景比成功场景更能证明工程能力。**
一个只会演示顺利路径的候选人，会被认为没上过线。

**准备清单**：
- [ ] 断网也能跑（用 mock）
- [ ] 所有依赖已装好
- [ ] 日志级别调到 INFO（不要 DEBUG 刷屏）
- [ ] 提前跑一遍，确认没有惊喜

## 9.8 五个雷区

1. **说不清自己的贡献**："我们一起做的" → 面试官无法评估你
2. **数据没有基线**："效率提升 80%" 但说不出从多少到多少
3. **只会讲技术**：问"业务价值"就卡壳
4. **不敢说不足**：一被问"有什么问题"就说"没什么问题"
5. **夸大**：说"上线服务全公司"，一问只有 3 个人用

## 9.9 毕业项目（第 9 章的实践）

从下面挑 **1 个**，端到端做完（需求 → 数据 → 实现 → 部署 → 度量 → 汇报）：

| 选项 | 内容 | 覆盖能力 |
|---|---|---|
| **A 广告异常监控** | 每日扫描搜索词/活动，异常推送 + 周报 | 数据 + 规则 + 告警 |
| **B 差评归类与质量周报** | 差评文本归类 + 按 ASIN 汇总 + 给工厂的举证 | 文本 + 评估 + 汇报 |
| **C 结算差异自动定位** | 月末对账桥 + 差异归因 + 异常清单 | 数据 + 对账 + 财务沟通 |
| **D 政策问答助手** | RAG + 引用 + 拒答 + 使用埋点 | 检索 + 评估 + 推广 |

**硬性要求**：
1. 有可运行代码 + 测试
2. 有一页纸作品集
3. 有前后对比数据（基线要写清来源）
4. 有已知不足
5. 能在 15 分钟内讲完并扛住 10 个追问

## 9.10 过关标准

- [ ] 一页纸作品集（八段齐全，含取舍与不足）
- [ ] 15 分钟讲述稿，其中"取舍"占 4 分钟
- [ ] 30 题追问里，能顺畅回答 ≥ 24 题
- [ ] 简历 3 条，每条都有数字或口径
- [ ] 5 分钟 demo 脚本，含一个故意失败的场景
- [ ] 能说出"如果重做会改什么"（至少 2 点，且是真的）

→ 去做 `练习与自测.md`。
