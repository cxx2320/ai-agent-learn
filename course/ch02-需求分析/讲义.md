# 第 2 章 · 需求分析：从"抱怨"到"可验收需求"

> **本章目标**：把一个模糊的抱怨，变成一份**别人能照着验收**的需求文档。
>
> **为什么这是岗位第一职责**：JD 第一条就是"业务需求分析"。技术做错可以改，**方向做错全白干**。
> 这门课后面 7 章的技术，全部服务于"把本章写下的需求实现出来"。

---

## 2.1 一个残酷的比例

跨境公司里，AI 项目失败的原因分布大致是：

```
方向错（做了没人要的东西）  ████████████████████  ~50%
数据拿不到 / 口径对不上      ██████████            ~25%
做出来了但没人用            ███████               ~17%
技术实现失败                ██                    ~8%
```

**技术失败只占 8%。** 所以这个岗位真正稀缺的能力，是"**判断该做什么**"，不是"会不会调模型"。

而"该做什么"的判断，靠的不是灵感，是**一套可重复的需求分析流程**。

---

## 2.2 需求从哪来：三个信号源

| 信号源 | 长什么样 | 怎么拿到 | 信噪比 |
|---|---|---|---|
| **抱怨**（主动找上门） | "这个太麻烦了""能不能自动弄" | 坐过去听、群里看 | 中：会提需求的人往往不是最痛的人 |
| **观察**（影子跟岗） | 她第 7 次复制粘贴同一列数据 | 坐她旁边看 30 分钟 | **高：最真实，最容易发现她自己都说不清的痛** |
| **指标异常** | ACOS 突然 22%→41%，退款率 6%→11% | 看报表、看告警 | 高：自带量化证据，最容易立项 |

> **新手只从"抱怨"拿需求，老手主要靠"观察"。**
> 因为用户会描述**他以为的问题**，而观察能看到**真实的问题**。

---

## 2.3 访谈：五个必问，三个禁问

### 五个必问

1. **"这件事你现在具体怎么做的？从打开哪个页面开始，走一遍给我看。"**
   → 拿流程，不拿评价。**一定要她操作，不要她复述。**
2. **"你上一次做这件事是什么时候？那次花了多久？"**
   → 要**具体案例**（critical incident），不要"平均情况"。人对平均值的记忆是编的。
3. **"这中间哪一步最烦 / 最容易错？"**
   → 定位痛点，也是 MVP 的切入口。
4. **"如果这件事彻底不用你做了，省下来的时间你会拿去干什么？"**
   → **验证价值**。答"不知道/还是干这些"说明这个需求价值不高。
5. **"如果我做出来的数字跟你手上的对不上，你会信谁？你会怎么核？"**
   → 提前挖出**口径**问题。这一问能救你后面 3 天。

### 三个禁问

| ❌ 别问 | 为什么 | 换成 |
|---|---|---|
| "你想要什么功能？" | 用户会给你**方案**（"我要个机器人"），而你要的是**问题** | "现在这件事最耗你时间的是哪一步？" |
| "你觉得 AI 能做吗？" | 用户不懂 AI，会给你错误的技术判断 | "如果这件事有人帮你做，你希望他做成什么样？" |
| "这个多久能做完？" | 用户不是工程师，估出来的数是承诺，会变成你的债 | 自己估，报区间 |

### 影子跟岗：30 分钟记录法

坐在用户旁边 30 分钟，只记五类事：

```
① 打开了什么（系统/页面/文件）
② 复制/抄了什么（字段、数值）
③ 粘贴到哪（Excel 哪个单元格、哪个群）
④ 卡在哪（等加载、找不到、算错重来）
⑤ 骂了什么（原话！原话里全是需求）
```

> 第 ⑤ 项最值钱。"又忘了这个站的时区"——一句话就是一个 bug 和一个功能点。

## 2.4 从抱怨到痛点陈述：必须带数字

### 阶梯模型

```
抱怨（主观）→ 痛点（可量化）→ 需求（能力）→ 方案（技术）→ 验收（标准）
```

新手最常犯的错：**从"抱怨"直接跳到"方案"**。

> 抱怨："每天弄报表太烦了"
> 新手方案："我给你做个 AI Agent，自动分析所有数据" ← 灾难的开始

### 痛点陈述模板（五要素）

```
【谁】+【什么场景下】+【做什么动作】+【多久一次 + 每次多久】+【不解决会怎样】
```

**改写示范**

| 原始抱怨 | 合格痛点陈述 |
|---|---|
| "每天弄报表太烦了" | 运营专员小李，工作日每天 9:00–10:30，需依次登录 8 个站点后台，下载业务报告与广告报告共 16 个 CSV，手工粘贴到一个 Excel 模板并计算 ACOS、退款率；**单次 90 分钟，每周 5 次**。上月因漏掉 US 站，一个高 ACOS 广告组**连续 3 天无人处理，估算多花 800 美元**。 |
| "广告词太多了看不过来" | 广告投手老王，每周一上午处理上周搜索词报告，**约 4,000 行**，靠眼睛筛否定词，**耗时 2.5 小时**，且只能看前 300 行。上月一个词**花费 1,200 美元、0 转化**，是老板发现的。 |
| "差评没人管" | 差评每天 **8–15 条**（8 站点合计），目前只在评分下降时才人工抽查，**无归类、无归因**；近 3 个月有 **2 次**因同类质量问题（"用两周就坏"）连续差评导致评分掉 0.3，**恢复用了 6 周**。 |

### 自检：你的痛点陈述合格吗？

- [ ] 有具体角色（不是"运营部"）
- [ ] 有频率和耗时（数字）
- [ ] 有"不解决的损失"（钱、时间、风险）
- [ ] **没有出现任何技术名词**（说了"AI""模型""自动化"就是跑偏了）

## 2.5 需求卡：把痛点变成一句用户故事

标准格式：

```
作为 <角色>，
我想要 <能力>，
以便 <业务价值>。
```

**关键区别**：

| ❌ 错（夹带方案） | ✅ 对（只要能力） |
|---|---|
| 我想要一个基于 GPT 的 Agent | 我想要在 8:30 前看到 8 个站点的昨日核心指标汇总 |
| 我想要爬虫 | 我想要不登录后台也能拿到昨天的广告花费 |
| 我想要个 RAG 知识库 | 我想要问"这个新规对我有没有影响"时能查到出处 |

> 准则：**用户故事里出现模型名、框架名、技术名词 = 写错了。** 技术选型是你的工作，不是用户的工作。

配套三个字段：**现状流程（As-Is）**、**目标流程（To-Be）**、**验收标准**。
模板见 `templates/需求卡-一页PRD-验收标准.md`。

## 2.6 验收标准：这一章真正的手艺

**验收标准的唯一判据：第三方 5 分钟内能判"通过/不通过"，不吵架。**

### 三原则

1. **可判定**：没有形容词。"快""准""好用""智能"全部禁止。
2. **有边界**：必须覆盖异常路径——**数据缺失、接口失败、空数据、重复执行、超时**。
3. **绑数字**：时间 / 数量 / 误差 / 成本，至少一个。

### Given / When / Then

```
给定 <前提>
当   <触发>
则   <可观测结果>
并且 <附带断言>
```

### 烂 vs 好（背下来这几组）

| ❌ | ✅ |
|---|---|
| 系统要快 | 单站点日报生成 ≤ 30 秒；8 站点全量 ≤ 4 分钟 |
| 数据要准 | 抽 20 个 ASIN 与后台核对：销售额误差 = 0，ACOS 误差 ≤ 0.1 个百分点 |
| 要好用 | 新用户不看文档，3 分钟内独立完成一次日报生成 |
| 出错要提示 | 站点文件缺失时，输出中明确列出缺失站点名且不得静默跳过；连续 2 天缺失 @ 负责人 |
| 要能扩展 | MVP 支持 US/UK/DE；JP 明确不在本期范围 |
| 要稳定 | 连续 10 个工作日定时执行，成功率 10/10，失败自动重试 1 次 |

### 反向压力测试（自己先打自己）

拿到一条 AC，问四个问题：

- 数据是空的会怎样？
- 接口挂了会怎样？
- 用户输错了会怎样？
- 这个数谁来核？拿什么核？

**答不上来的，就是没验收。**

## 2.7 一页纸 PRD：九个格子

不要写 20 页。**一页纸，九个格子，能说服老板、能约束自己。**

1. 背景与问题（Why now，带数字）
2. 目标 / **非目标**（Non-Goal 比 Goal 重要）
3. 用户与场景
4. 功能范围（MVP，带优先级）
5. **不做清单**（Out of Scope）
6. 输入与输出（系统、字段、频率、**时区**）
7. 验收标准
8. 成功指标（现状 → 目标 → 怎么测）
9. 风险与依赖 + 里程碑

> 第 5 格"不做清单"是新手最常省略、老手必写的一格。
> 没有不做清单，项目一定在第三周开始膨胀，然后在第六周死掉。

## 2.8 范围控制：MVP 四刀切法

一个需求总能被切小。四刀按顺序切：

| 刀 | 切什么 | 例子 |
|---|---|---|
| **① 砍输入** | 只接一个站点 / 一个报表 | 先只做 US 站的业务报告，不接广告 |
| **② 砍输出** | 先给最粗糙的交付形式 | 先输出 Markdown 到控制台，不做网页、不推送 |
| **③ 砍自动化** | 先手动触发 | 先 `python run.py`，跑通了再上定时 |
| **④ 砍智能** | 先用规则，后上模型 | 先用 if/else 做阈值告警，跑两周看误报率再考虑模型 |

**判据**：MVP 必须是**一周内能跑出结果给人看**的版本。
超过一周才有第一个可见产物 → 切得不够小。

**迭代节奏**：v0.1（能出数）→ v0.2（自动发）→ v0.3（多站点）→ v0.4（异常预警）→ v1.0（业务日常使用）。

## 2.9 优先级：RICE + 第三轴

### RICE

```
Score = (Reach × Impact × Confidence) / Effort

R  Reach      : 影响的人数或频次（例：5 人 × 每周 5 次 = 25）
I  Impact     : 3 极大 / 2 高 / 1 中 / 0.5 低 / 0.25 微小
C  Confidence : 1.0 有数据 / 0.8 有访谈 / 0.5 靠猜
E  Effort     : 人天
```

### 第三轴：数据可得性 D（跨境项目专用）

| D | 情况 | 处理 |
|---|---|---|
| 3 | 现成文件，每天能下载 | 直接做 |
| 2 | 有 API / 有 ERP 导出，但要申请权限 | 先并行推进权限 |
| 1 | 数据在别人手里 / 拿不到 | **降级为 P2，或改需求** |

> **铁律：数据拿不到的需求，优先级直接归零。**
> 跨境项目最常见的死法不是技术难，是"做完了发现要平台 API 权限，申请要 3 个月"。

## 2.10 ROI：怎么证明"有可衡量业务价值"

JD 原话："让 AI 工具融入实际工作流程，并产生**可衡量的业务价值**"。这是面试必问。

### 三段式算账

```
① 省时收益 = 人数 × 单次耗时(h) × 频次/周 × 52 × 时薪
② 避损收益 = 历史事故频率(次/年) × 单次损失
③ 成本     = 开发人天 × 人天成本 + 运行成本(API/服务器/月 × 12) + 维护(人天/月 × 12)

回收期(月) = 成本 ÷ (月收益)
```

### 计算示例

```
小李：1.5 h/天 × 5 天/周 × 52 周 = 390 h/年 × 80 元/h = 31,200 元/年
避损：过去 6 个月 2 次漏站，平均损失 800 美元 ≈ 5,760 元 → 年化 11,520 元
成本：开发 4 人天 × 800 = 3,200；运行 30 元/月 × 12 = 360；维护 0.5 人天/月 × 12 = 4,800
年净收益 ≈ 31,200 + 11,520 − 8,360 = 34,360 元；回收期 ≈ 1.2 个月
```

### ⚠️ 高级陷阱：省下来的工时 ≠ 业务价值

这是**面试官会追问、90% 的人答不上来**的点。

> "你省了小李 1.5 小时/天，可她本来也是按时下班，那这 31,200 元价值在哪？"

**能过关的回答方式**（三选一，或组合）：

1. **释放到高价值动作**：这 1.5 h 现在用于看 3 个重点 ASIN 的广告结构优化，预计贡献毛利 X 元/月（要有依据，比如试点一个月的对比）。
2. **用避损论证**：不谈省时，谈"把发现异常的延迟从 3 天缩短到 1 天"。过去 6 个月因此类延迟损失 2 次 × 800 美元 → 可衡量。
3. **用质量论证**：手工拼表错误率 8%（月均 2 次算错导致决策偏差），自动化后 0。

> 记住：**"省了时间"是过程指标，"少亏了钱 / 多赚了钱 / 少犯错了"才是业务价值。**

## 2.11 风险清单：六类，提前写

| 类型 | 典型表现 | 提前动作 |
|---|---|---|
| **数据风险** | 拿不到 / 权限要 3 个月 / 格式每月变 | 第 1 周就申请权限，做 PoC 验证 |
| **口径风险** | 你的数 ≠ 业务手上的数 | 访谈第 5 问，先对齐口径再写代码 |
| **用户风险** | 上线了没人用 / 还是用回 Excel | 找 1 个种子用户参与设计 |
| **准确率风险** | 模型偶尔错，用户一次就不再信 | 设"人审"环节 + 置信度标注 |
| **成本风险** | token 花费超预期 / 调用量涨 | 设预算上限 + 缓存 + 小模型兜底 |
| **合规风险** | 客户个人信息出境、平台数据条款 | 只用聚合数据，不留原文字段 |

## 2.12 六个高频错误（每条都能让项目死一次）

1. **把方案当需求**："做个 AI 客服" —— 这是方案。需求是"客服每天花 2 h 回复重复问题"。
2. **一次做太大**：3 周做"8 站点全自动 + 网页 + 告警 + 模型分析" → 第 4 周交付不出来，信任崩塌。
3. **验收标准写形容词**：结果就是"我觉得还差点意思"无限循环。
4. **不问口径就开工**：做完后业务说"这不是我们的销售额"，返工。
5. **只找提需求的人，不找用的人**：提需求的是主管，天天用的是专员，专员不点头就没人用。
6. **不做"不做清单"**：范围每周膨胀一点，最后什么都做一半。
