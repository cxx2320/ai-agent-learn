## 模板 3：验收标准三原则 + 写法对照

### 三原则
1. **可判定**：第三方 5 分钟内能判"通过/不通过"，不产生争议。
2. **有边界**：包含异常路径（数据缺失、接口失败、超时、空数据）。
3. **绑数字**：时间、数量、准确率、成本，至少有一个数字。

### Given / When / Then 写法

```
给定 <前提条件>
当   <触发动作>
则   <可观测的结果>
并且 <附带断言>
```

### 烂 vs 好 对照

| ❌ 烂 | ✅ 好 |
|---|---|
| 系统要快 | 单站点日报生成 ≤ 30 秒，8 站点全量 ≤ 4 分钟 |
| 数据要准确 | 与后台报表抽样 20 个 ASIN，销售额误差 = 0，ACOS 误差 ≤ 0.1pp |
| 要好用 | 新用户不看文档，3 分钟内能独立跑出一次日报 |
| 出错要有提示 | 某站点文件缺失时，消息中明确列出缺失站点名，且不得静默跳过；连续 2 天缺失则 @ 负责人 |
| 支持多站点 | MVP 支持 US/UK/DE 三站；JP 站不在本期范围 |

### 反向自检：你的 AC 能被这样打回吗？

- "如果数据是空的会怎样？" → 没写就是没验收
- "如果接口挂了会怎样？" → 没写就是没验收
- "如果用户输错了会怎样？" → 没写就是没验收
- "这个数谁来核对？拿什么核？" → 没写就是没验收
