## 任务 1｜术语自测答案

**填空**

1. 两个 **子体（Child ASIN）**，挂在同一个 **父体（Parent ASIN）** 下。
2. **FBA**；**FBM**。
3. TACOS = **广告花费 ÷ 总销售额**（总销售额 = 广告销售额 + 自然销售额）。
4. ROAS = 1 ÷ 25% = **4**。
5. CTR = 600/40,000 = **1.5%**；CVR = 24/600 = **4%**。
6. DOI = **当前可售库存 ÷ 日均销量**（日均销量取最近 7/30 天滚动平均，口径要写清）。
7. 低于 **1%**；后果：**账户被限流/暂停销售权限（suspension）**、Listing 被下架、Buy Box 丢失。
8. 从 **工厂（国内）** 到 **海外仓 / 平台仓（FBA 仓）**。
9. **UTC（世界标准时间）**。
10. 卖家负责 **供货（把货送到平台仓、定供货价）**；平台负责 **定价、流量、物流、售后**。

**判断**

11. ❌ 错。销售额涨，退款、广告费、佣金、仓储费可能涨得更多。第 1.9 节的案例就是"销售额涨、利润为负"。
12. ❌ 错。**关广告会丢流量和排名**。ACOS 高要看"这个广告是否在抢自然单"（自己跟自己竞争）、以及自然单占比。TACOS 才是整体健康度指标。正确动作是**优化**（否词、调出价、改匹配方式、优化 Listing 转化率），不是一刀切关停。
13. ✅ 对。取消单、未付款单、ERP 抓单延迟、时区切日、SKU 映射错误都会导致差异。**这是常态，不是 bug。**
14. ❌ 错。有字符上限、移动端只显示前 70–80 字符、堆词会被降权（关键词堆砌），可读性还影响转化率。
15. ✅ 对（但要注意前提：**仅限该广告组/该匹配类型下**，且要看够量级再否，否则误杀长尾）。

**自测评分**：15 题 × 2 分 = 30 分。得 24 分以上（≥12/15 正确）算过关。

## 任务 2｜指标计算与业务诊断

### 先把数算完

| 指标 | B0C1AAA | B0C1BBB |
|---|---|---|
| CTR = 点击/曝光 | 1,800/120,000 = **1.50%** | 800/80,000 = **1.00%** |
| CVR（订单/点击） | 60/1,800 = **3.33%** | 32/800 = **4.00%** |
| CVR（订单/Session） | 60/1,500 = **4.00%** | 32/700 = **4.57%** |
| AOV = 销售额/订单 | 3,000/60 = **$50** | 1,280/32 = **$40** |
| ACOS = 花费/广告销售额 | 450/2,000 = **22.5%** | 160/320 = **50.0%** |
| TACOS = 花费/总销售额 | 450/3,000 = **15.0%** | 160/1,280 = **12.5%** |
| 广告订单占比 | 40/60 = **66.7%** | 8/32 = **25.0%** |
| 自然订单 | **20 单** | **24 单** |
| 毛利（不含广告） | 3,000×40% = **$1,200** | 1,280×35% = **$448** |
| 广告后利润 | 1,200−450 = **$750** | 448−160 = **$288** |
| 广告后利润率 | 750/3,000 = **25.0%** | 288/1,280 = **22.5%** |
| 退款率 | 300/3,000 = **10.0%** | **0%** |

### 逐题要点

**1–3.** 见上表。
第 2 题的**关键**：为什么两个 CVR 不一样？因为 **Session（访客数）> 点击**时说明一个访客点了多次（或广告点击被去重），所以"订单/Session"会更高。
👉 **面试点**：一定要问清"你们的 CVR 是订单/点击还是订单/Session"——报出来的数可能差 20%。

**4–5.** 见上表。注意 **自然销售额 = 3,000 − 2,000 = $1,000，自然订单 20 单，自然 AOV = $50**，和整体一致，说明数据自洽。

**6–7. 这道题是本任务的精髓。**

> BBB 的 ACOS 50% 很差，TACOS 12.5% 却比 AAA 的 15% 更好——**矛盾吗？不矛盾。**

- **ACOS 衡量"广告本身效率"**：BBB 每卖 1 美元广告销售额要花 0.5 美元，效率差。
- **TACOS 衡量"生意的广告负担"**：BBB 的销售里 75% 是自然单，广告只花了 160 美元，占总销售 12.5%，所以整体负担轻。
- **结论**：BBB 是"自然流量为主、广告在补量但补得很浪费"的品；AAA 是"高度依赖广告"的品。

**再深一层（加分回答）**：
```
BBB 广告 CVR = 8/610 = 1.3%     ← 极低
BBB 自然 CVR = 24/(800−610) = 24/190 = 12.6%  ← 极高
```
**广告流量和自然流量的质量差了 10 倍** → 广告投到了不精准的词/人群上。这不是"广告该不该关"的问题，是"**广告投歪了**"。

**8–9.** 见上表。
第 9 题：**AAA 的 10% 退款率更值得警惕**。
理由：① 退款直接冲减利润，而且损失不止货值（还含 FBA 配送费、退货处理费、不可售损耗）；② 退款率高会拉高 ODR、拉低评分，影响 Buy Box 和流量；③ 10% 明显高于行业常见 3%–8% 区间；④ BBB 退款为 0，说明供应链质量不是普遍问题，AAA 是**单品问题**。

**10. 决策题（评分重点，不是算得对就行）**

两种都是好答案，讲清链路即可：

**答案 A（推荐）：去治 BBB 的广告精准度**
```
看到：BBB 广告 CVR 1.3%，自然 CVR 12.6%，ACOS 50%
推断：广告匹配到了不相关流量（大词、宽泛匹配、自动广告跑偏）
动作：下载搜索词报告 → 高花费零转化词加否定 → 收紧匹配类型/降低泛词出价 →
      把预算挪给转化高的精准词
验证：一周后看广告 CVR 是否 ≥3%、ACOS 是否降到 30% 以下、总订单和自然排名是否不掉
```
**为什么优先**：这是"花出去的钱立刻能省下来"的改动，且不动 Listing、不冒险。

**答案 B：去查 AAA 的 10% 退款**
```
看到：AAA 退款 300/3,000，10%
推断：产品/描述不符/质量问题
动作：拉退货报告 → 看退货原因分布 → 看差评关键词
验证：下次 200 单的退款率是否降到 6% 以下
```
**为什么也对**：退款是纯亏损，且会累积成账号风险。但**见效慢**（要改产品/改 Listing）。

> 批改时我会看：你有没有**先定位再动手**，有没有写**验证方法**。只写"优化广告"没有链路 = 不及格。

## 任务 3｜口径陷阱

**3.1 "3,000 美元"为什么不能直接算利润（列 3 条即可，满分答案）**

1. **未扣退款**：AAA 当天退了 300，实际净销售 2,700。
2. **未扣广告费**：610 美元广告费不在业务报告里，在广告后台。
3. **未扣平台费用**：佣金（约 15%）、FBA 配送费、仓储费都在**结算报告**里，业务报告没有。
4. **未扣货品成本**：采购 + 头程在 ERP/采购系统里。
5. **金额性质问题**：这是"下单时"的销售额，含优惠券/促销前或后的口径不清，也不含买家付的运费/税（口径因报表而异）。

> 👉 **一句话**：业务报告的销售额是"**毛销售额**"，利润表要的是"**净额**"。中间隔了 5 层扣减。

**3.2 跨月广告费算哪个月**

- **业务口径**：按"广告花费发生日"归属（广告报表按站点时区切日）。
- **财务口径**：按"平台实际扣费/结算日"归属（结算报告按 UTC）。
- **结论**：两者本来就不同基准，**必须先把口径写进文档，并用映射表对齐**，否则每月必吵。
- 加分点：提到"**用 UTC 统一入库，再按站点时区派生业务日期**"这个工程做法。

**3.3 归因窗口（人话版）**

> "买家点了广告之后 7 天（或 14 天）内下的单，都算这条广告的功劳。"
> 后果：① 同一笔订单可能被算给多条广告/多个广告组 → 广告销售额**虚高**；② 昨天的广告销售额今天看是一个数，**过几天会变**（回溯更新）→ 你做的日报数字会"自我修正"，业务方会以为你算错了。

**3.4 ERP 58 单 vs 后台 60 单（排查顺序）**

| 顺序 | 可能原因 | 怎么查 |
|---|---|---|
| 1 | **时区切日不一致**（最常见） | 对齐 ERP 的"日期"字段是站点时区还是北京时间；美西 vs 北京差 15–16 h |
| 2 | **订单状态**：pending / cancelled 未付款单 | 后台按"创建时间"算，ERP 只抓已付款/已发货 |
| 3 | **FBM 单抓取失败** | 看 ERP 抓单日志/失败队列 |
| 4 | **SKU ↔ ASIN 映射缺失**（变体漏配） | 查该 ASIN 的子体是否都绑了 SKU |
| 5 | **同步延迟**（T+1 才落库） | 对比今天的数和刷新后的数 |
| 6 | **促销/赠品**：买赠被算 1 单还是 2 单 | 查该日的 promotion 记录 |

> 👉 **排查顺序的原则**：**先查"系统性/时间性"原因（时区、状态、延迟），再查"配置性"原因（映射），最后才怀疑"数据丢失"。**
> 新手最爱一上来就怀疑"是不是接口漏了单"，90% 的情况其实是时区和状态口径。

## 任务 4｜数据流图批改要点

**及格线**：6 个环节填完整，且"关键字段"是**真实字段名**（`session` / `acos` / `sku` / `order_id` / `settlement_id`），不是"销量""花费"这种中文泛指。

**加分项**：
- 指出 ERP 是"中间汇聚层"（订单/库存/利润都从这过）——这就是为什么第 3 章要重点处理 ERP 导出表。
- 指出有些环节**没有系统**（选品表、备货表是人工 Excel）——这是最容易长出 AI 工具的地方。
- 画出"广告报表 + 业务报告 + 结算报告"三张表在 ASIN/日期 上 join 的关系。

**常见低分点**：
- 只写"下载报表"，没写"下载哪个报表、什么格式、多久一次"。
- 忽略"售后"和"财务"两环（新手最常漏，而这两环恰恰是数据最脏、最有价值的地方）。

## 任务 5｜痛点盘点批改要点

**及格标准（逐条打分）**

| 维度 | 合格 | 不合格 |
|---|---|---|
| 有具体的人 | "广告投手小王" | "运营部门" |
| 有具体频率 | "每周一上午" | "经常" |
| 有具体耗时 | "2.5 小时" | "很花时间" |
| 现在怎么做 | 写到步骤（"①登录后台②选报表③下载④拼到模板⑤算 ACOS⑥发给主管"） | "手动处理" |
| 出错后果 | "漏了一个词，多烧 800 美元" | "不好" |
| 数据在哪 | "广告后台搜索词报告 CSV，站点时区" | "系统里" |
| 能否用 AI | 有判断 + 理由 | 只写"能" |

**自检答案参考**：讲义 1.7 的 10 条里，**大约只有 3 条真正需要大模型**（Listing 生成、差评/评论洞察、客服草稿、政策问答）。
第 1、2、7、8 条（报表拼接、否定词、对账、库存预警）——**规则 + SQL + 脚本就能解决，不需要模型。**

> 👉 这是本章最重要的一句话：
> **能用规则解决的，绝不用大模型。** 大模型的成本、延迟、不确定性都是负债。
> 一个成熟的 AI 应用工程师，80% 的时间在写确定性代码，20% 才在调模型。

## 任务 7｜加分题批改要点

标题结构一般是：`品牌 + 品类核心词 + 关键属性 + 适用场景/兼容设备 + 卖点 + 数量/规格`
- **品类词**：wireless charger stand / charging station
- **卖点词**：fast charging / 3 in 1 / foldable / adjustable
- **长尾词**：compatible with iPhone 16 / for desk

不要求准确，要求你**意识到"标题是关键词工程，不是文案写作"**。
